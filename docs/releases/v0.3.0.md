# edownloader 0.3.0 — now on Linux

**edownloader runs on Linux.** The same app, the same single field, in a `.deb`, an `.rpm` or an AppImage, for x86_64 and arm64.

## Highlights

- 🐧 **Linux, x86_64 and arm64.** A `.deb` for Debian, Ubuntu and Mint, an `.rpm` for Fedora and openSUSE, and an AppImage for everything else. Built on Ubuntu 22.04, so it requires glibc 2.35 or newer; that includes Ubuntu 22.04+, Debian 12+, Fedora 36+ and current openSUSE releases.
- 🧰 **Tools in one click, there too.** yt-dlp, ffmpeg and Deno install from the banner from their official Linux builds, checksums verified, as on Windows. aria2 comes from your distribution: the `.deb` and `.rpm` bring it as a dependency, and with the AppImage the banner tells you the command.
- 🔄 **The AppImage updates itself** when it is in a folder you can write to. Like the Windows app, it downloads the next version in the background, checks it against the release key, and takes its place when you close it or click **Restart to update**. The `.deb` and `.rpm` tell you a version is out; your package manager installs it. The AppImage also carries its update information, with a `.zsync` beside it, so AppImageUpdate, Gear Lever or AppImageLauncher can update it too, downloading only what changed.
- 🪟 **At home on the desktop.** Its own title bar on GNOME, KDE and the rest, edges and corners that resize the window, the desktop's own file chooser for cookie files through the XDG portal, and the interface in your system language.
- 🖱️ **Title bar shortcuts, everywhere.** Double-click the title bar to maximize or restore the window, on Windows too; on Linux, right-click it for the window menu.

Also included: Inter and JetBrains Mono ship with the app on Linux, so it looks the same on every distribution (Windows keeps Segoe UI and Consolas) · the cookie file dialog on Windows copes with any translated title · a step-by-step guide in the README for signing in to YouTube with the open-source [Cookies Extractor](https://github.com/chekun/cookies-extractor) extension, whose exports are now covered by the tests.

## Install

**Windows:** already on 0.2.0? edownloader updates itself. New here? Download **`edownloader_0.3.0_x64-setup.exe`** below and run it.

**Linux:** pick the package for your system below.

| System | x86_64 | arm64 |
| --- | --- | --- |
| Debian, Ubuntu, Mint… | `edownloader_0.3.0_amd64.deb` | `edownloader_0.3.0_arm64.deb` |
| Fedora, openSUSE… | `edownloader-0.3.0-1.x86_64.rpm` | `edownloader-0.3.0-1.aarch64.rpm` |
| Anything else | `edownloader_0.3.0_x86_64.AppImage` | `edownloader_0.3.0_aarch64.AppImage` |

```sh
sudo apt install ./edownloader_0.3.0_amd64.deb      # Debian, Ubuntu
sudo dnf install ./edownloader-0.3.0-1.x86_64.rpm   # Fedora
chmod +x edownloader_0.3.0_x86_64.AppImage && ./edownloader_0.3.0_x86_64.AppImage
```

On first launch, click **Install** in the yellow banner to fetch the tools (about 200 MB, mostly ffmpeg), unless your system already has them.

> [!NOTE]
> On Windows, the installer is signed with a self-signed certificate, so SmartScreen may show *"Windows protected your PC"* on first launch. Click **More info → Run anyway**.

`SHA256SUMS.txt` contains the checksum of every package. The `.AppImage.zsync` files are for AppImage update tools. `latest.json` is what the updater reads: the Windows installer's and the AppImages' addresses and signatures.

## Known limitations

- No macOS build yet.
- The Linux packages are not signed with a GPG key: check them against `SHA256SUMS.txt`.
- The arm64 Linux packages are built and tested natively by the release workflow, but have not yet been manually tested end to end on an arm64 desktop.
- RHEL 9 and its rebuilds (glibc 2.34) are too old for these packages.
- With the AppImage, direct links and magnets need aria2 from your distribution (`sudo dnf install aria2`, `sudo apt install aria2`).
- Rare technical messages stay in English.
- The download queue is not saved when you close the app.
